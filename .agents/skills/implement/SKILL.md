# 実装の開始・修正

`$implement <Issue URL・番号 | Backlog 課題キー | PR URL・番号>` で使う。番号だけでは Issue と PR の区別がつかない場合は、会話で指定された対象から判断する。

1. Issue 本文・Backlog 課題、または既存 PR の本文とレビュー指摘を読み、実装の前に変更方針を共有する。
2. `AGENTS.md` と `CLAUDE.md` の規約に沿って作業ブランチを用意する。既存 PR の修正はその PR のブランチを使い、手元の変更と混ざる場合は別の worktree を使う。
3. 変更し、関連テストや lint で確認する。PR のレビュー対応は、指摘ごとに修正と検証結果を報告する。
4. 対象ファイルをステージしてコミットする。Backlog キーがある場合はコミットメッセージに含める。

仕様確認から PR 作成と CI 監視まで一括で進める場合は `$implement-auto` を使う。
