# 選択的フォールバックの設計と費用試算 — Task 5

- 作成日: 2026-09-09
- 対象: `Backend/internal/services/interview/stt_fallback.go`

## 1. 何を再送するか

通常発話は `gpt-4o-mini-transcribe` のまま処理し、以下のときだけ
`gpt-4o-transcribe` へ同じ音声を再送する。

| 条件 | reason | 根拠 |
|---|---|---|
| STT が失敗した | `stt_error` | 結果が無い |
| 結果が空 | `empty_result` | 結果が無い |
| 「聞き取れませんでした」相当 | `unintelligible` | 結果が無い |
| 音声長に対して文字数が極端に少ない | `too_short_for_duration` | 取りこぼしの疑い |
| 「本社」を含む | `role_confusion` | Task 4 の実測（後述） |

`role_confusion` だけが「一見成功しているのに再送する」条件である。
Task 4 で **mini は補助語なしだと「御社」を 8/8 で「本社」と誤認**し、
補助語ありでも 3/8 は誤認したまま残ることを実測した。
面接において「御社」と「本社」は意味が変わるため、この語だけは取り直す価値がある。

「本社が東京にあります」のような正当な発話も再送対象になるが、
再送しても結果が変わらないだけで、認識内容が壊れることはない。

### 意図的に採用しなかった条件

依頼の候補にあった「数字・英語・固有名詞を含むケース」「重要な回答として判定されたケース」
は入れていない。面接の発話の大半が該当し、**再送率がほぼ100%になって
mini を使う意味が消える**ため。§3 の損益分岐を参照。

## 2. 過剰な再送を防ぐ仕掛け

- **音声秒数はフロントの録音設定（128 kbps＝16,000バイト/秒）から推定する。**
  当初は調査用の合成音声（約3,800バイト/秒）を根拠に4,000バイト/秒としており、
  **4倍過大**に見積もっていた。10秒の発話を40秒とみなすため、
  下の「文字数が少ない」判定が短い回答で軒並み誤爆し、再送率＝費用を押し上げていた。
- **3秒未満の音声は長さ判定を行わない。** 「はい」のような短い相槌は
  正しく認識できていても文字数が少ない。ここを免除しないと正常な発話を再送し続ける。
- **下限は 1.0 文字/秒。** 日本語の自然な発話は 4〜7 文字/秒なので、
  「明らかに何も取れていない」水準まで絞っている。
- **既定モデルが既に `gpt-4o-transcribe` なら再送しない。** 同じモデルへ再送しても
  結果は変わらず、費用だけが倍になる。
- **再送が失敗・空なら元の結果を残す。** 面接は止めない。

## 3. 費用（試算）

| モデル | 単価 |
|---|---|
| gpt-4o-transcribe | $0.006 / 分 |
| gpt-4o-mini-transcribe | $0.003 / 分 |

面接1回15分、うち学生の発話を 7.5 分と仮定する。

| 構成 | 面接1回あたり |
|---|---|
| 全て mini | $0.0225 |
| 全て 高精度 | $0.0450 |
| mini + 再送率 r | $0.0225 + $0.045 × r |

**損益分岐点は再送率 50%。** これを超えると
「mini + フォールバック」は「高精度モデル単独」より高くつく。

| 再送率 | 面接1回 | 高精度単独との比 |
|---|---|---|
| 10% | $0.0270 | 60% |
| 20% | $0.0315 | 70% |
| 30% | $0.0360 | 80% |
| **50%** | **$0.0450** | **100%（分岐点）** |

再送率が 30% を超え続ける場合、フォールバックを増やすのではなく
**既定モデルを高精度へ戻す方が安く、かつ品質も高い。**

## 4. 再送率をどう見るか

`LogSTTObservation` が STT 1回ごとに `fell_back` を出す。
`FellBack` は**採用可否ではなく再送を実行した時点**で立てる。
課金は実行で発生するため、採用しなかった再送も費用には含まれる。

```
fell_back=true の件数 / STT 呼び出し総数 = 再送率
```

## 5. 応答時間への影響

再送は STT をもう一度叩くため、そのターンの応答が STT 1回分（実測で1〜3秒）遅くなる。
設計書は Turn 経路の応答遅延を「2〜4秒」とし、これを
「模擬面接としては明確に不自然」と評価している。再送が乗るとさらに伸びる。

通常のSTTのタイムアウトは60秒で、再送も同じだと**最悪ケースは STT だけで120秒**になる。
再送は元の結果があるうえでの上積みなので、この待ち時間には見合わない。
**再送側は20秒で打ち切る**（`sttFallbackTimeout`）。打ち切っても元の結果で会話は続く。

## 6. 未検証

- **実測の再送率がまだ無い。** §3 は単価と仮定から引いた式であって、
  合成音声・実発話のいずれからも再送率そのものは測っていない。
  ステージングで `fell_back` を集計するまで、本番の追加費用は確定しない。
- 「本社」による再送が、実発話でどれだけの頻度で起きるか。
  Task 4 は難易度の高い1音声を8回試行した結果であり、面接全体の頻度ではない。
- 再送で実際に「本社」→「御社」へ改善するかは、mini の誤認ケースを
  高精度モデルへ流し直す実測が必要（Task 6 と併せて行う）。
