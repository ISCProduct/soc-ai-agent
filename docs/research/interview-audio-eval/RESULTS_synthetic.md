## この結果で判断してはいけないこと

**合成音声のみの結果です。** README にあるとおり、発音・雑音・個人差を再現していません。

- 人間の発話、雑音、反響、小声、早口、言い淀みは含まれていません
- 8ケースは母数として小さく、固有名詞は13語しかありません
- 端末差（ノートPC / スマートフォン / 外付けマイク）も未検証です

**mini への切り替え可否は、実発話（Phase 2）を測るまで決められません。**
本結果が言えるのは「合成音声の範囲では差が出なかった」までです。

## 計測時に見つかった評価側の問題

初回の実行では固有名詞の正解率が **60%** と出ましたが、これは**計測の誤り**でした。

1. `manifest.jsonl` の `checks` に、実際に発話へ現れる語（`Go`, `MySQL`）と、
   評価観点のラベル（`一般語`, `言い淀み`, `無音区間`）が混在している。
   ラベルまで照合すると、現れるはずのない語を不正解として数える。
   → 正解文に含まれる語だけを照合対象とするよう修正（`CheckableKeywords`）
2. 表記ゆれ（`30パーセント` → `30%`）を誤変換として数えると、CERが 0.08 に跳ねる。
   → 意味の差を見る `SemanticCER` を別指標として追加

**指標の作り方次第で「miniは精度が低い」という誤った結論になり得ました。**
評価基盤そのものを検証してから数値を読むこと。

## 実音声を録音条件別に評価する（#1484）

投資バックログ（SOCAIAGENT-314）の優先順位(1)。合成音声だけの結果を
本番品質の根拠にしないため、`sttbench` に録音条件別・由来別の集計を追加した。

### manifest.jsonl の追加フィールド

| フィールド | 意味 | 既定 |
| --- | --- | --- |
| `condition` | 録音条件（`clean` / `noisy` / `reverb` / `fast` / `hesitation` など） | `unspecified` |
| `source` | 音声の由来。`synthetic`（合成）か `real`（実発話） | `synthetic` |

既存フィクスチャは全て合成なので、未指定は `synthetic` として扱う。

### 使い方

```sh
# 全件。出力に「由来別」「録音条件別」の内訳が付く（2種以上あるとき）
go run ./cmd/sttbench -manifest <path>/manifest.jsonl -format wav -out <リポジトリ外>

# 特定の録音条件だけを評価する
go run ./cmd/sttbench -manifest <path>/manifest.jsonl -condition noisy -out <リポジトリ外>
```

由来別・条件別に CER・固有名詞正解率・数値正解率・失敗率が出る。
母数の無い指標は `-`（0=全滅と区別）。

### 注意

- 実発話・認識本文・APIキーはリポジトリ・ログに出さない（従来どおり）
- 実API結果はリポジトリ外へ
- **実発話そのものの収集**（同意・保存期間・削除方針）は別タスク。
  本変更は「集まった実音声を条件別に評価できる状態」を作るところまで
