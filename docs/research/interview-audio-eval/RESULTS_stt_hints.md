# STT補助情報（prompt）の検証結果 — Task 4

- 実行日: 2026-09-09
- 音声: `manifest.jsonl` の8ケース + 難易度の高い固有名詞を含む追加音声1件

## 1. API の対応状況（実測）

公式ドキュメントのページには `prompt` パラメータの記載が見つからなかったため、
**実APIで直接確認**した。

| モデル | prompt 受理 |
|---|---|
| gpt-4o-transcribe | ⭕ |
| gpt-4o-mini-transcribe | ⭕ |
| whisper-1 | ⭕ |

3モデルとも受理し、エラーにならない。

## 2. 幻覚の副作用（依頼の懸念事項）

「補助語を追加することで、存在しない語を無理に出力させる副作用がないか」を検証した。

音声に一切含まれない語（`Kubernetes, Terraform, Rust, GraphQL, 株式会社エンタープライズソリューションズ, データサイエンティスト`）を渡して3ケースで比較。

**結果: 出力は1文字も変わらなかった。幻覚は発生しない。**

```
clean-introduction  補助語なし / 無関係な補助語 → 完全に同一
short-answer        補助語なし / 無関係な補助語 → 完全に同一
hesitation          補助語なし / 無関係な補助語 → 完全に同一
```

## 3. 改善効果（8回試行）

難易度の高い音声で測定。正解は
「**御社**の**キュービットソリューションズ**という製品に興味があります。ラムダアーキテクチャの**設計**も学びました。」

| 条件 | 「御社」正解 | カタカナ社名 |
|---|---|---|
| gpt-4o-transcribe / 補助語なし | **8/8** | 7/8 |
| gpt-4o-transcribe / 補助語あり | **8/8** | **8/8** |
| gpt-4o-mini-transcribe / 補助語なし | **0/8** | 6/8 |
| gpt-4o-mini-transcribe / 補助語あり | **5/8** | **8/8** |

### 最も重要な発見

**mini は補助語なしだと「御社」を8回中0回しか正しく認識しない。全て「本社」になる。**

面接で「御社」と「本社」は意味が変わる。補助語で 5/8 まで改善するが、
高精度モデルの 8/8 には届かない。

**これは mini を採用する場合の具体的なリスクである。**
合成音声8ケースの一般的な指標（CER・固有名詞正解率）では両モデルに差が出なかったが、
この語だけを見ると明確な差がある。

### 補足: 「設計」→「設定」は両モデルとも 0/8

補助語の有無・モデルに関わらず一貫して誤変換した。音声合成側の発音の問題と考えられ、
実発話での再確認が必要。

## 4. 途中で誤った結論を出しかけた点

初回の1回試行では次の結果が出た。

```
補助語なし: 本社のキュービットソリューションズという製品に…   ← カタカナで正しい
補助語あり: 本社のQbit Solutionsという製品に…                ← 英語表記に化けた
```

これを見て「補助語が精度を悪化させた」と判断しかけたが、
**8回試行すると補助語なしでも `Qbit` に化けており、mini の実行ごとのばらつきだった。**

**1回の試行で結論を出してはいけない。** mini は同じ入力でも結果が安定しない。

## 5. 実装

`BuildSTTHints(companyName, companyReading, position, companyInfo)`

出力例:

```
御社, 株式会社サンプルソフト, サンプルソフト, バックエンドエンジニア, AWS, Go, MySQL, SaaS, TypeScript
(企業未選択) 御社
```

- 「御社」は企業情報の有無に関わらず常に含める（§3の理由）
- 企業情報は**文章のまま渡さず技術用語だけを抽出**する。文章を渡すと補助語ではなく
  「続きの文脈」として扱われ、認識が引きずられる
- `models.SkillScore` は補助語に使わない。カテゴリ（論理性・技術志向など）と
  スコアしか持たず、「Go」「AWS」のような固有の技術名を持たないため
