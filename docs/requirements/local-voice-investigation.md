# PRD: AI面接をローカルLLM＋音声マルチモーダルで賄えるか（調査）

- Issue: [#1209](https://github.com/ISCProduct/soc-ai-agent/issues/1209) (SOCAIAGENT-310)
- 種別: 調査
- 関連: 親エピック [#792](https://github.com/ISCProduct/soc-ai-agent/issues/792) / 推論基盤 [#793](https://github.com/ISCProduct/soc-ai-agent/issues/793) / 音声方針 [#1193](https://github.com/ISCProduct/soc-ai-agent/issues/1193)
- 最終更新: 2026-09-09

## 1. 背景

AI面接は現在 OpenAI の Turn 経路（STT → LLM → TTS）で動いている。
ローカルLLMと音声マルチモーダルへ寄せることで、コスト削減と機密性の向上が
見込めるかを判断したい。

ただし [#1209](https://github.com/ISCProduct/soc-ai-agent/issues/1209) は一度
「実運用実績がゼロの機能に投資すべきか判断できない」として破棄した経緯がある。
本調査は**判断材料そのものを実機で作る**ことを目的とし、実装は対象外とする。

## 2. 目的

「置き換えられるか」を、遅延・品質・メモリ・コストの実測値で判断できる状態にする。

### 成功条件

- 現行のコスト構造（どこに費用がかかっているか）を実数で示せる
- ローカル構成の1ターン遅延を実測し、現行（2〜4秒）と比較できる
- 8GB 環境（#792 の制約）で成立するかを、実測メモリで判断できる
- 採用/不採用の推奨と、その根拠を示せる

### 非目標

- PoC 実装、フラグ切替、staging/本番への組み込み
- 深掘り・採点ロジックの変更
- ファインチューニング（[#268](https://github.com/ISCProduct/soc-ai-agent/issues/268) の非蒸留方針は本調査の範囲外）

## 3. 前提と制約

- 検証環境: Apple M3 Max / 36GB / GPU 30コア / macOS 26.6.2
- **本番は AWS ECS Fargate（x86・GPUなし）**。検証環境とハードウェアが根本的に違う
- 親エピック #792 のメモリ上限は 8GB
- 面接セッションの実効上限は 30分（`frontend/lib/interview.ts:6`）

## 4. 測る対象

| 項目 | 測り方 |
|---|---|
| 現行コスト | 公表単価 × 実装の呼び出し回数。コード内の定数は信用しない（過去に10倍の乖離があった） |
| STT | 日本語音声39秒を処理する時間、原稿との一致率、実メモリ |
| LLM | 実際のシステムプロンプトでの応答開始まで(TTFT)・生成速度・日本語品質・実メモリ |
| TTS | 生成時間、日本語音声の有無、コスト |
| 通し | 発話終了 → 面接官の音声生成完了までの合計 |

## 5. 判断に必要な問い

1. コストのどこが重いのか（LLMか、音声か）
2. ローカル化して現行と同等の遅延に収まるか
3. 8GB で成立するか。成立しない場合、何が足りないか
4. 品質は面接として許容できるか
5. 本番（Fargate）にそのまま持ち込めるか

## 6. リスク

- **合成音声で精度を測ると実際より良く出る。** 人間の音声・雑音・言い淀みでは低下する
- 検証環境と本番のハードウェアが違うため、**実測値をそのまま本番の見積もりに使えない**
- ローカル化は運用対象（モデル配布・更新・障害対応）が増える。コスト削減分と相殺されうる
