# 卒業生の進路実績（学生向け、#2032）

学生が、自分の学校の先輩がどの企業に就職したかを見られるようにする。管理画面の
`/admin/graduate-employments`（登録・編集）とは別に、学生向けの読み取り専用の経路を置く。

## 画面

- `/graduate-outcomes`: 企業ごとの人数（年度別）を、人数の多い順に一覧する。卒業年度・業界で絞り込める。共通メニュー（`SIDEBAR_NAV_ITEMS`）から行ける
- 企業詳細（`/company/[id]`）: 「先輩の進路実績」カードで、その企業への年度別・職種別の人数を出す。実績が無ければカードごと出さない

## API（学生）

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/graduate-outcomes?year=&industry=` | 企業ごとの人数（年度別）と、絞り込みの選択肢（年度・業界） |
| GET | `/api/graduate-outcomes/companies/:id` | 1社への年度別・職種別の人数。企業が無い（学生に見せない）なら 404 |

## 範囲とプライバシー

- 学生は `EchoUserAuth` から決め、**学校もその学生の `users.school_id` から決める**（クエリで学校を指定させない）。どのクエリも `graduate_employments.school_id` で絞り、削除済みは除く
- 学校の学園（`schools.organization_id`）が本人の学園と一致するときだけ実績を出す（`AssessmentRepository.FindUserSchoolID` と同じ fail-close）。学生が存在しない・退会済みなら 401
- 企業は学生向けの企業表示と同じ条件で絞る（有効・未削除・審査前のゲスト投稿でない）
- 学校が未登録の学生には実績を出さない（`school_linked: false`）。他校の実績は見せない
- **卒業生の氏名・学科・メモ（`graduate_name` / `department` / `note`）は読まない**。学生に出すのは人数だけ
- `school_id` が未設定の古い登録（学校名の自由記述だけの行）は、どの学校の学生にも出ない
- 特定の企業を推す表示ではなく事実の提示なので、並びは人数の多い順（同数は企業名順）にし、おすすめの印は付けない

## 少人数の扱い（3人未満は人数を出さない）

母数の小さい学校では「企業 × 年度」「企業 × 職種」で 1 人と分かると、学内では誰のことか特定できる。
そのため、人数が 3 人未満（`graduateoutcome.MinCount`）の区分は数を出さない。

秘匿は**最小の区分（企業 × 年度 × 職種）**で行い、画面に出す数はどれも「見せる最小の区分の和」だけで作る。
隠した人数はどの数字にも入らないので、合計から内訳を引いても、年度別と職種別を比べても、年度で絞り込む前後を
比べても、隠した人数は求まらない（以前は正確な合計を出したまま内訳だけを隠していたので、引き算で分かった）。

- 企業の `total`・年度別・職種別・一覧の `total` は、見せる区分の和。1社の年度別の和も職種別の和も `total` と一致する
- 3 人未満の区分があれば `total_few`（と `by_year_few` / `by_position_few`）を立てる。画面は「7人＋少数」のように、数に入れていない卒業生がいることだけを出す
- 見せる区分が1つも無い企業は `total: null`（画面は「少数」）。企業の合計が 3 人以上でも、区分ごとに 3 人未満なら人数は出さない
- 一覧の並びは人数の多い順。見せる区分の無い企業は、末尾に企業名順で置く

## 年度と職種

- 卒業年度が未登録（0・NULL）の実績は `year: 0` で返し、画面は「年度未登録」と出す。合計には含め、絞り込みの選択肢には出さない
- 職種は、その企業の求人（`company_job_positions.company_id = graduate_employments.company_id`）だけを結ぶ。別企業の求人 ID を指す行は「職種の登録なし」に寄せる
