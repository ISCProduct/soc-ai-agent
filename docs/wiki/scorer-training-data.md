# 採点モデルの学習データの書き出し（#2168）

軽量の面接採点モデル（#1834）を学習するために、学生の面接をマスキングして S3 に書き出すジョブの運用手順です。
同意の扱い・退会時の削除の方針は [データプライバシー設計](./data-privacy.md) の「学習利用の同意（#2167 / #2168）」を見てください。

---

## 本番で実行する前に揃えるもの（運用ゲート）

**次の3つが揃うまで、本番（production）では実行しません。** ステージングや手元で、ダミーのデータを使って動かすのは構いません。

| 前提 | 状態 | 揃っていないと困ること |
|------|------|------------------------|
| 同意の撤回・退会のときに、書き出し済みのデータ（S3）を消す処理（#2168 の次の PR。`hardDeleteUserData` からの削除を含む） | 未 | 撤回・退会した学生のデータが S3 に残り、消す手段が無い |
| 出力先バケットの infra（サーバー側の暗号化・公開アクセスのブロック・保存期間1年のライフサイクル・IAM の範囲。書き込みは実行ロールだけ、読み取りは学習用と管理者だけ） | 未 | 書き出したデータを、学習と関係のないロールや人が読めてしまう |
| 既存の学習データの書き出し（`training.Service.Export`、RAG の `/training/export`）の扱いの整理 | 未 | 同意を見ない経路が残る |

揃ったらこの表を更新してください。

## 何を書き出すか

- 対象は「学習に使ってよい学生」だけです。条件は `trainingEligibleUsers`（`Backend/internal/repositories/training_scorer_export_repository.go`）の1か所にまとめています。
  - `allow_training_use = 1`（学習利用に同意している）
  - `withdrawn_at IS NULL`（退会していない）
  - `role = 'student' AND is_guest = 0`（学生で、ゲストではない）
- 面接は `status = 'finished'`・未削除・LLM の採点（`interview_reports.scores_json`）があるものだけです。採点が壊れている（ルーブリックの検証を通らない）面接と、学生の回答が無い面接は書かずに数えます。
- 学生ごとに、書く直前と書いた後の2回、条件を判定し直します。書いた後に外れていれば（その間に同意を撤回した・退会した）、そのファイルを消します。消せなければ実行を失敗にします。

### マスキング

すべての質問と回答を、必ず `masking.New(masking.DefaultRules(), 辞書)` に通します。**マスキングを外す設定はありません。**
辞書は、その学生の氏名（表記の揺れを含む）・本人のメールアドレスとローカル部・学校名（DB の名称と本人の自由記述）・企業名から作ります。
AI の質問もマスキングします（質問に氏名が入るため）。

### 利用者 ID の扱い

DB の利用者 ID・面接 ID は出力しません。代わりに、秘密鍵（`TRAINING_EXPORT_HMAC_KEY`）を使った HMAC-SHA256 を書きます。
鍵を変えると同じ学生の `subject` が変わり、撤回・退会のときに書き出し済みのデータを見つけられなくなります。**鍵は変えないでください。**

## 実行のしかた

管理者の API はありません。アプリの外で、実行ロールを絞ったタスクとして CLI を動かします。

```bash
cd Backend
TRAINING_EXPORT_HMAC_KEY=<32バイト以上の秘密鍵> \
TRAINING_EXPORT_S3_URI=s3://<bucket>/<prefix> \
go run ./cmd/training-export
```

| 環境変数 | 必須 | 内容 |
|----------|------|------|
| `TRAINING_EXPORT_HMAC_KEY` | ✓ | 利用者 ID を HMAC にする秘密鍵。32 バイト以上。ほかの秘密鍵と兼用しない |
| `TRAINING_EXPORT_S3_URI` | ✓ | 出力先。`s3://bucket/prefix` の形。バケットの直下は指定できない |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | ✓ | DB の接続先（サーバーと同じ） |
| `AWS_REGION` | | 既定は `ap-northeast-1`。認証情報は AWS SDK の既定の探し方（実行ロールなど）で読む |

- 鍵か出力先が無い・形が違うときは、DB にもつながずにエラーで終わります。
- `APP_ENV=production` でなければ、`.env` を読みます（サーバーと同じ）。
- Ctrl+C・SIGTERM（コンテナの停止・タイムアウト）で取り消せます。取り消した回も、監査ログには「失敗」が残ります。
- 終わると、学生の人数・面接の件数・書き出さなかった面接の件数・出力先を表示します。

## 出力の形

```
<prefix>/runs/<実行ID>/subjects/<subject>.jsonl   学生1人ぶん。1行が面接1回
<prefix>/runs/<実行ID>/manifest.json             最後に書く。これがある回だけが書き終えた回
```

- 実行 ID は「UTC の秒までの時刻＋8桁のランダムな16進」（例 `20261117T010203Z-a1b2c3d4`）です。同じ秒に二重に起動しても衝突しません。
- 学生ごとにファイルを分けているのは、撤回・退会のときに、ほかの学生のデータを書き直さずにその人のファイルだけを消せるようにするためです。
- オブジェクトはサーバー側の暗号化（AES256）を必ず指定して書き、公開の ACL は付けません。

JSONL の1行（`format_version` は今 `1`）:

| キー | 内容 |
|------|------|
| `format_version` | 行の形の版 |
| `sample_id` | 面接 ID の HMAC |
| `subject` | 利用者 ID の HMAC |
| `template_version` | 面接のテンプレートの版 |
| `turns` | `[{"q": 質問, "a": 回答}]`（マスキング済み） |
| `labels` | ルーブリックの軸ごとの LLM の採点 |
| `label_source` | 常に `"llm"` |

`manifest.json` には `run_id`・`exported_at`・`label_source`・`label_note`・`rubric_keys`・`masking_tokens`（置き換えに使った記号）・学生の人数・面接の件数・ファイルの一覧が入ります。

### LLM ラベルの扱い

`labels` は LLM の採点で、教員の採点ではありません。LLM の出力を学習に使うのは、#1834 の軽量採点モデルに限った例外です。

- 学習したモデルのレポートに、LLM ラベルで学習したことを書く（学習スクリプト #2170 がヘッダとレポートに書く）
- 精度の評価は、教員が採点したセット（#2172）で行う
- ほかの学習（LoRA など）には使わない

## 監査ログ（`training_scorer_export_runs`）

書き出し1回につき1行です。最初に `running` で作り、終わったら結果を書きます。監査ログを作れなければ何も書き出しません。

| 列 | 内容 |
|----|------|
| `status` | `running` / `succeeded` / `failed` |
| `started_at` / `finished_at` | 開始・終了の日時 |
| `student_count` / `session_count` | 書き出した学生の人数・面接の件数 |
| `destination` | 出力先（`s3://bucket/prefix/runs/<実行ID>/`） |
| `error_message` | 失敗したときのエラー。`subject`（16進64桁）は伏せる |

個人を特定するもの（利用者 ID・HMAC にした ID を含む）は持たないので、退会時のパージの対象にはしていません。
`running` のまま残っている行は、途中でプロセスが落ちた回です。学習には `manifest.json` がある回だけを使います（学習スクリプトはマニフェストの無いディレクトリを読みません）。
