# 採点モデルの学習データの書き出し（#2168）

軽量の面接採点モデル（#1834）を学習するために、学生の面接をマスキングして S3 に書き出すジョブの運用手順です。
同意の扱い・退会時の削除の方針は [データプライバシー設計](./data-privacy.md) の「学習利用の同意（#2167 / #2168）」を見てください。

---

## 本番で実行する前に揃えるもの（運用ゲート）

**次の表の「未」がすべて揃うまで、本番（production）では実行しません。** ステージングや手元で、ダミーのデータを使って動かすのは構いません。

| 前提 | 状態 | 揃っていないと困ること |
|------|------|------------------------|
| 同意の撤回・退会のときに、書き出し済みのデータ（S3）を消す処理（下記「書き出し済みのデータの削除」） | 済 | 撤回・退会した学生のデータが S3 に残り、消す手段が無い |
| 削除の定期実行（`-sweep-only` を毎日動かすスケジュール。**同時に1つだけ**動かし、書き出しとも重ねない）と、サーバーへの書き出しの設定（パージで消すため） | 未（infra） | 取り消しが次の書き出しまで反映されない・パージで消えない・マニフェストの書き直しが重なる（下記） |
| サーバーの起動時に「学習データの削除の設定」のエラーのログが出ていないことの監視 | 未（infra） | 設定の誤りでも起動は続くので、見落とすとパージでの削除だけが黙って無効になる（定期実行の削除は動く） |
| 出力先バケットの infra（サーバー側の暗号化・公開アクセスのブロック・保存期間1年のライフサイクル・IAM の範囲。書き込みは実行ロールだけ、読み取りは学習用と管理者だけ。**バージョニングは使わない**か、古いバージョンをすぐに失効させる） | 未 | 書き出したデータを、学習と関係のないロールや人が読めてしまう・バージョニングが有効だと、消したファイルの古いバージョンが残る |
| 既存の学習データの書き出し（`training.Service.Export`、RAG の `/training/export`）の扱いの整理 | 済（#2355 で、管理者向けの書き出しを同意済みの学生に絞った。RAG の `/training/export` は DB を読まず、管理者向けの書き出しの出力を受け取って整形するだけ。条件は [データプライバシー](./data-privacy.md#学習データの書き出しの条件)） | 同意を見ない経路が残る |

揃ったらこの表を更新してください。

## 何を書き出すか

- 対象は「学習に使ってよい学生」だけです。条件は `trainingEligibleUsers`（`Backend/internal/repositories/training_scorer_export_repository.go`）の1か所にまとめています。
  - `allow_training_use = 1`（学習利用に同意している）
  - `withdrawn_at IS NULL`（退会していない）
  - `role = 'student' AND is_guest = 0`（学生で、ゲストではない）
- 面接は `status = 'finished'`・未削除・LLM の採点（`interview_reports.scores_json`）があるものだけです。採点が壊れている（ルーブリックの検証を通らない）面接と、学生の回答が無い面接は書かずに数えます。
- 学生ごとに、書く直前と書いた後の2回、条件を判定し直します。書いた後に外れていれば（その間に同意を撤回した・退会した）、そのファイルを消します。消せなければ実行を失敗にします。

### マスキング

すべての質問と回答を、必ず `masking.New(masking.DefaultRules(), 辞書)` に通します。**マスキングを外す設定はありません。**
辞書は、その学生の氏名（表記の揺れを含む）・本人のメールアドレスとローカル部・学校名（DB の名称と本人の自由記述）・企業名から作ります。
AI の質問もマスキングします（質問に氏名が入るため）。

### 利用者 ID の扱い

DB の利用者 ID・面接 ID は出力しません。代わりに、秘密鍵（`TRAINING_EXPORT_HMAC_KEY`）を使った HMAC-SHA256 を書きます。
鍵を変えると同じ学生の `subject` が変わり、撤回・退会のときに書き出し済みのデータを見つけられなくなります。**鍵は変えないでください。**

## 実行のしかた

管理者の API はありません。アプリの外で、実行ロールを絞ったタスクとして CLI を動かします。

```bash
cd Backend
TRAINING_EXPORT_HMAC_KEY=<32バイト以上の秘密鍵> \
TRAINING_EXPORT_S3_URI=s3://<bucket>/<prefix> \
go run ./cmd/training-export
```

| 環境変数 | 必須 | 内容 |
|----------|------|------|
| `TRAINING_EXPORT_HMAC_KEY` | ✓ | 利用者 ID を HMAC にする秘密鍵。32 バイト以上。ほかの秘密鍵と兼用しない |
| `TRAINING_EXPORT_S3_URI` | ✓ | 出力先。`s3://bucket/prefix` の形。バケットの直下は指定できない |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | ✓ | DB の接続先（サーバーと同じ） |
| `AWS_REGION` | | 既定は `ap-northeast-1`。認証情報は AWS SDK の既定の探し方（実行ロールなど）で読む |

- 鍵か出力先が無い・形が違うときは、DB にもつながずにエラーで終わります。
- `APP_ENV=production` でなければ、`.env` を読みます（サーバーと同じ）。
- Ctrl+C・SIGTERM（コンテナの停止・タイムアウト）で取り消せます。取り消した回も、監査ログには「失敗」が残ります。
- 書き出しの前に、必ず「書き出し済みのデータの削除」（下記）を行います。削除に失敗したら書き出しません。
- 終わると、消したファイルの数と、学生の人数・面接の件数・書き出さなかった面接の件数・出力先を表示します。

## 書き出し済みのデータの削除（同意の取り消し・退会）

画面で約束している「オフにすると、書き出し済みのデータも削除する」と、退会時の削除を、次の2つで行います（`Backend/internal/services/training/scorerexport/sweep.go`）。

| いつ | 何を消すか | 呼ぶところ |
|------|------------|------------|
| 書き出しのたびの最初と、`-sweep-only` の定期実行（毎日） | いま学習に使ってよい学生（上の条件）**以外**のファイルを、すべての回から | `go run ./cmd/training-export`（`-sweep-only` は消すだけ） |
| 退会のパージ（猶予の30日の後） | その学生のファイルを、すべての回から | サーバーのパージ（`UserDeletionService.purgeOne`） |

```bash
cd Backend
TRAINING_EXPORT_HMAC_KEY=... TRAINING_EXPORT_S3_URI=... go run ./cmd/training-export -sweep-only
```

- 同意を取り消した学生と、退会した学生（猶予期間中も含む）は「学習に使ってよい学生」から外れるので、次の削除で消えます。取り消しを早く反映するため、`-sweep-only` を**毎日**動かします。
- パージは、利用者の行が DB から消えた後でも、利用者 ID から `subject` を作って消せます。面接動画などの S3 の削除と同じく、DB のコミット後の best-effort で、結果は監査ログ（`user.purge` の `training_data_deleted_files`・`training_data_error`）に残します。消し損ねたものは次の削除が拾います。
- サーバーでパージから消すには、サーバーにも `TRAINING_EXPORT_HMAC_KEY` と `TRAINING_EXPORT_S3_URI` を設定します（CLI と同じ値）。どちらも無ければ、パージでは消しません（定期実行の削除が消します）。片方だけなどの誤りは、起動時にエラーのログを出します。
- 消すときは、先にその回の `manifest.json` から消すファイルを外し（`files`・`student_count`・`session_count`・`file_sessions` を直す）、その後でファイルを消します。順番を逆にすると、マニフェストの書き直しに失敗したときに「載っているのに無いファイル」が残り、学習スクリプトがその回を読めなくなるためです。マニフェストを直せなかった回のファイルは消さず、失敗にします。
- **マニフェストの書き直しは排他していません**（S3 に読み書きのロックが無いため）。定期実行の削除とパージの削除が同じ回で同時に走ると、後から書いたほうが、先に外したファイルをマニフェストに戻すことがあります。そのため、削除のたびに、マニフェストのある回はすべて照合し、**載っているのに実在しないファイルもマニフェストから外します**（一覧の後に書かれたファイルを誤って外さないよう、外す前にその回を一覧し直して確かめます）。ずれは次の削除で直ります。重なりを減らすため、定期実行は同時に1つだけ動かします（運用ゲート）。S3 の条件付き書き込み（`If-Match`）での排他は、今後の改善の候補です。
- `file_sessions` の無い、この仕組みより前に書いたマニフェストでは、ファイルと `student_count` は直しますが、`session_count` は直せない（引く数が分からない）ので、そのまま残します（多めの値になる）。CLI はその回の数を表示します。学習スクリプトは `files` だけを読み、件数は使いません。
- 学生のファイルは読みません。必要な権限は、キーの一覧・`manifest.json` の読み書き・学生のファイルの削除だけです（サーバーに学習データを読む権限を付けなくてよい）。
- 対象の学生の一覧を取れないときは、何も消さずに失敗にします（一覧が空のまま進めて、全員分を消さないため）。
- 取り消した後に、もう一度同意した学生のデータは、次の削除の時点で「学習に使ってよい学生」に戻っていれば消しません。

## 出力の形

```
<prefix>/runs/<実行ID>/subjects/<subject>.jsonl   学生1人ぶん。1行が面接1回
<prefix>/runs/<実行ID>/manifest.json             最後に書く。これがある回だけが書き終えた回
```

- 実行 ID は「UTC の秒までの時刻＋8桁のランダムな16進」（例 `20261117T010203Z-a1b2c3d4`）です。同じ秒に二重に起動しても衝突しません。
- 学生ごとにファイルを分けているのは、撤回・退会のときに、ほかの学生のデータを書き直さずにその人のファイルだけを消せるようにするためです。
- オブジェクトはサーバー側の暗号化（AES256）を必ず指定して書き、公開の ACL は付けません。

JSONL の1行（`format_version` は今 `1`）:

| キー | 内容 |
|------|------|
| `format_version` | 行の形の版 |
| `sample_id` | 面接 ID の HMAC |
| `subject` | 利用者 ID の HMAC |
| `template_version` | 面接のテンプレートの版 |
| `turns` | `[{"q": 質問, "a": 回答}]`（マスキング済み） |
| `labels` | ルーブリックの軸ごとの LLM の採点 |
| `label_source` | 常に `"llm"` |

`manifest.json` には `run_id`・`exported_at`・`label_source`・`label_note`・`rubric_keys`・`masking_tokens`（置き換えに使った記号）・学生の人数・面接の件数・ファイルの一覧・`file_sessions`（ファイルごとの面接の数。削除のときに学生のファイルを読まずに件数を直すため）が入ります。

### LLM ラベルの扱い

`labels` は LLM の採点で、教員の採点ではありません。LLM の出力を学習に使うのは、#1834 の軽量採点モデルに限った例外です。

- 学習したモデルのレポートに、LLM ラベルで学習したことを書く（学習スクリプト #2170 がヘッダとレポートに書く）
- 精度の評価は、教員が採点したセット（#2172）で行う
- ほかの学習（LoRA など）には使わない

## 監査ログ（`training_scorer_export_runs`）

書き出し1回・削除（`-sweep-only` と書き出しの前の削除）1回につき1行です。最初に `running` で作り、終わったら結果を書きます。監査ログを作れなければ何も書き出さず、何も消しません。パージからの削除は、`audit_logs` の `user.purge` に残します。

| 列 | 内容 |
|----|------|
| `kind` | `export`（書き出し）/ `sweep`（書き出し済みのデータの削除） |
| `status` | `running` / `succeeded` / `failed` |
| `started_at` / `finished_at` | 開始・終了の日時 |
| `student_count` / `session_count` | 書き出した学生の人数・面接の件数（`export`） |
| `deleted_file_count` | 消した学生のファイルの数。回ごとに数える（`sweep`） |
| `destination` | 出力先（`export` は `s3://bucket/prefix/runs/<実行ID>/`、`sweep` は `s3://bucket/prefix/runs/`） |
| `error_message` | 失敗したときのエラー。`subject`（16進64桁）は伏せる |

個人を特定するもの（利用者 ID・HMAC にした ID を含む）は持たないので、退会時のパージの対象にはしていません。
`running` のまま残っている行は、途中でプロセスが落ちた回です。学習には `manifest.json` がある回だけを使います（学習スクリプトはマニフェストの無いディレクトリを読みません）。
