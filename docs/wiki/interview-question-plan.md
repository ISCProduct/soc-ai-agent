# AI面接の質問計画（人物像の軸と経歴型）

AI面接の質問は、セッション開始時に作る「質問キュー」（`interview_question_states`）を1問ずつ消化して進みます。
このページは、そのキューに **企業の人物像の軸スロット** を加える仕組み（#2274 段階1）と、
守っている制約を書きます。実装は `Backend/internal/services/interview/` の
`interview_axis.go` / `interview_question_planner.go` / `interview_turn_question_plan.go` /
`interview_resume_context.go`。

## キューの組み立て

優先順は次のとおりです。

1. 必須カスタム質問（企業ポータルで設定したもの）
2. 企業別ヒント（RAG が調査した候補。カスタム質問が無いときだけ）
3. 標準トピック（自己紹介・志望動機 / 職務経験・実績 / 強み・弱み / キャリアビジョン / 逆質問）
4. 推奨カスタム質問

**軸スロットがあるとき**は、3 のうち冒頭（自己紹介・志望動機）と末尾（逆質問）を残し、
中間の3トピックを軸の数だけ後ろから置き換えます。軸が無いときは従来どおり標準5トピックです。

## 軸の選定（決定的なコード。LLM は呼ばない）

`CompanyWeightProfile`（10軸・0〜100）から上位最大3軸を選びます。職種別のプロファイルが
あれば職種別、無ければ企業単位を使います（職種名は `company_job_positions.title` との完全一致で引きます）。

| 定数 | 値 | 意味 |
|---|---|---|
| `maxTargetAxes` | 3 | 軸の最大数 |
| `minAxisScore` | 60 | 軸として選ぶ重視度の下限 |
| `minAxisSpread` | 20 | 最大と最小の差がこれ未満なら「識別できない」として軸なし |

プロファイルが無い、全軸が似た値（既定の50のまま等）、全軸が60未満のときは軸を選びません。
未審査のゲスト企業・DB 未登録企業も軸なし（`BuildCompanyBrief` と同じ可視条件）。
しきい値はテスト（`interview_axis_test.go`）で固定しています。値を変えるときは根拠を残してください。

選ばれた軸は `interview_question_states.target_axis` に記録します（軸スロットとその深掘りだけ。他は NULL）。
採点には使いません。

## 軸スロットの質問

- 軸ごとに主質問を1つ。深掘りは既存の `NeedsDeepening` 機構（最大1回）を使います。
- 質問文の土台は軸ごとの定型の行動事象型質問（出来事・自分の役割・判断・結果）。企業名や企業の事実を含みません。
- プロンプトには「評価したい観点を応募者に伝えない」「企業の求める人物像を断定しない」
  「企業の事実として触れてよいのは【企業情報】にある項目だけ。無ければ一般の行動質問にする」を入れます。
  人物像は LLM による相対評価の推定値で、企業が公式に述べた要件ではないためです。
- 【企業情報】には、公開済み（`published` かつ `is_active`）の求人の `required_skills` / `preferred_skills` が入ります。
- 追質問の生成（既存の1回のLLM呼び出し）には、企業情報（非信頼テキストとして囲む）と軸を渡します。

## 経歴型の面接（履歴書の参照）

軸スロットの質問（とその深掘り）のときだけ、本人の最新の履歴書の本文
（`ResumeTextBlock` を結合し、2000字で切る）を非信頼テキストとして system プロンプトへ渡します。

- 読むのは**面接セッションの所有者の履歴書だけ**です（`user_id` と `organization_id` の両方で絞る）。
- 履歴書が無ければ何も足しません。具体的な出来事があればそれを起点に聞き、無ければ一般の行動質問にします。
- 経歴が薄い学生を不利にしないよう、学業・サークル・アルバイトも材料にする指示を入れています。
- 履歴書が登録済みの学生には、面接のロビー（企業選択画面・準備画面）に
  「登録済みの履歴書を質問づくりに参照します」と表示します。

## 就職差別につながる質問の除外

面接官（アシスタント）側の生成文に、家族構成・出身地・本籍・国籍・宗教・支持政党・思想などを
聞く表現（`ContainsDiscriminatoryQuestion`）が含まれたら、

- 面接官の返答: 1回だけ再生成し、それでも含まれるなら軸なしの定型質問に差し替える。
- 追質問: 生成文を捨ててテンプレートの追質問にする（LLM 呼び出しを増やさない）。

学生の回答には適用しません。正規表現による決定的な検査で、言い換えや婉曲表現は拾えません
（「出身大学」「宗教学」「設計思想」などの正当な語は除外済み）。

## 採点には使わない

`interview_report.go` と `UpdateScoresFromInterviewReport` は人物像・軸を参照しません
（#2123: 同じ回答を企業文脈あり・なしで採点して有意差を出さない条件）。人物像は質問の選択にだけ使います。
テスト（`TestReportPromptIsIndependentOfAxes`）で、レポートのプロンプトと採点コードが軸を参照しないことを確認しています。

## 守っている制約

- 面接中に Web 検索・企業調査の LLM 呼び出しを足さない（追加の LLM 呼び出しは追質問の既存の1回だけ。
  差別質問の再生成は面接官の返答に限った1回）。
- start-turn / turn / report のレスポンス形は変えない。
- スキーマ変更は `Backend/migrations/20261114004733_add_interview_question_target_axis` の up/down。
