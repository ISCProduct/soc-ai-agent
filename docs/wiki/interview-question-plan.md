# AI面接の質問計画（人物像の軸と経歴型）

AI面接の質問は、セッション開始時に作る「質問キュー」（`interview_question_states`）を1問ずつ消化して進みます。
このページは、そのキューに **企業の人物像の軸スロット** を加える仕組み（#2274 段階1）と、
守っている制約を書きます。実装は `Backend/internal/services/interview/` の
`interview_axis.go` / `interview_question_planner.go` / `interview_turn_question_plan.go` /
`interview_resume_context.go`。

## キューの組み立て

優先順は次のとおりです。

1. 必須カスタム質問（企業ポータルで設定したもの）
2. 企業別ヒント（RAG が調査した候補。カスタム質問が無いときだけ）
3. 標準トピック（自己紹介・志望動機 / 職務経験・実績 / 強み・弱み / キャリアビジョン / 逆質問）
4. 推奨カスタム質問

**軸スロットがあるとき**は、3 のうち冒頭（自己紹介・志望動機）と末尾（逆質問）を残し、
中間の3トピックを軸の数だけ後ろから置き換えます。軸が無いときは従来どおり標準5トピックです。

## 軸の選定（決定的なコード。LLM は呼ばない）

`CompanyWeightProfile`（10軸・0〜100）から上位最大3軸を選びます。職種別のプロファイルが
あれば職種別、無ければ企業単位を使います（職種名は `company_job_positions.title` との完全一致で引きます）。

| 定数 | 値 | 意味 |
|---|---|---|
| `maxTargetAxes` | 3 | 軸の最大数 |
| `minAxisScore` | 60 | 軸として選ぶ重視度の下限 |
| `minAxisSpread` | 20 | 最上位の軸と全10軸の中央値の差がこれ未満なら「識別できない」として軸なし |

プロファイルが無い、上位が中央値と変わらない（既定の50のまま等）、全軸が60未満のときは軸を選びません。
最小値ではなく中央値と比べるのは、低い外れ値1軸だけで全体が「差がある」と判定されないためです。
選んだ軸は重視度のスコア降順（同点は表の順）に出題します。
境界値（差19/20、スコア59/60、外れ値1軸）はテストで固定しています。
未審査のゲスト企業・DB 未登録企業も軸なし（`BuildCompanyBrief` と同じ可視条件）。
しきい値はテスト（`interview_axis_test.go`）で固定しています。値を変えるときは根拠を残してください。

選ばれた軸は `interview_question_states.target_axis` に記録します（軸スロットとその深掘りだけ。他は NULL）。
採点には使いません。

## 軸スロットの質問

- 軸ごとに主質問を1つ。深掘りは既存の `NeedsDeepening` 機構（最大1回）を使います。
- 質問文の土台は軸ごとの定型の行動事象型質問（出来事・自分の役割・判断・結果）。企業名や企業の事実を含みません。
- プロンプトには「評価したい観点を応募者に伝えない」「企業の求める人物像を断定しない」
  「企業の事実として触れてよいのは【企業情報】にある項目だけ。無ければ一般の行動質問にする」を入れます。
  人物像は LLM による相対評価の推定値で、企業が公式に述べた要件ではないためです。
- 【企業情報】には、公開済み（`published` かつ `is_active`）の求人の `required_skills` / `preferred_skills` が入ります。
  軸ブロックには「この軸に関係するスキルがあれば、そのスキルを使った・伸ばした経験を聞く形で質問を具体化する」と明記しています。
- 軸スロットの質問と追質問に渡す企業情報からは、LLM 推定の「重視傾向」行を除きます（企業の事実ではないため）。
- 返答の長さは【基本ルール】の「2〜3文・150文字以内」を優先します。
- プロンプトの「現在のトピック」「残りトピック」「質問の進め方」は、軸を含むキューでは実際のキュー順・未実施数に合わせます
  （軸スロットは固定名「行動事象型（人物像）」。軸の名前は出しません）。軸なしのキューは標準5トピックのままです。

### 企業ごとの差別化の範囲（段階1）

企業を替えたときに質問が変わるのは、**軸の選定・重視度順・求人要件（必須/歓迎スキル）への結びつけ**に限ります。
軸ごとの「良い回答の観点」を使った質問生成・評価は**段階2**で行います。
人物像の軸は LLM による相対評価の推定値で、work_life_balance / stability を質問に読み替える部分も
解釈であり、根拠の整備は段階2です。標準トピックを軸で置き換える設計（後ろの中間トピックから置換）も段階1の暫定です。
- 追質問の生成（既存の1回のLLM呼び出し）には、企業情報（非信頼テキストとして囲む）と軸を渡します。

## 経歴型の面接（履歴書の参照）

軸スロットの質問（とその深掘り）のときだけ、本人の最新の履歴書の本文
（`ResumeTextBlock` を結合）から**学歴・職歴・資格・自己PR・志望動機の節だけ**を抜き出し、2000字で切って
非信頼テキスト（見出し【応募者の履歴書】）として system プロンプトへ渡します。

- 氏名・生年月日・年齢・性別・住所・電話・メール・本籍・国籍・家族などの属性欄は送りません。
  見出しで節を判定し、見出しが取れない履歴書は属性らしい行（定型パターン）と先頭の氏名らしき行を除外します。
  切り詰めは属性を除いたあとです。独自様式の履歴書は取りこぼし得ます（定型パターンの照合）。
- 履歴書が複数あるときは、テキストブロックがあるもののうち最新を使います（最新が本文空なら古いものにフォールバック）。

- 読むのは**面接セッションの所有者の履歴書だけ**です（`user_id` と `organization_id` の両方で絞る）。
- 履歴書が無ければ何も足しません。具体的な出来事があればそれを起点に聞き、無ければ一般の行動質問にします。
- 経歴が薄い学生を不利にしないよう、学業・サークル・アルバイトも材料にする指示を入れています。
- 履歴書が登録済みの学生には、面接のロビー（企業選択画面・準備画面）に
  「登録済みの履歴書を、面接の質問づくりに参照することがあります」と表示します。
  軸の質問のときだけ使うので、断定せず「参照することがあります」としています（文言は `RESUME_REFERENCE_NOTICE`）。

## 就職差別につながる質問の除外

面接官（アシスタント）側の生成文に、厚生労働省「公正な採用選考」の項目（家族構成・出身地・本籍・住宅状況・
国籍・宗教・支持政党・人生観・生活信条・尊敬する人物・思想・労働組合・学生運動・購読新聞雑誌・愛読書・
性別・年齢・結婚・出産・健康・障害・病歴など）を聞く表現（`ContainsDiscriminatoryQuestion`）が含まれたら、

- 面接官の返答: 質問を求めるターン（質問が残っているターン。終了挨拶と、面接官が答える「逆質問」ターンは除く）だけ、
  1回だけ再生成し、それでも含まれるなら軸なしの定型質問に差し替える。差し替えたら記録済みの質問文
  （`interview_question_states.question_text`）も実際に聞いた文に更新する。
- 追質問: 生成文を捨ててテンプレートの追質問にする（LLM 呼び出しを増やさない）。

学生の回答には適用しません。正規表現による決定的な検査で、言い換えや婉曲表現は拾えません。
「出身」は単独語でも検出しますが、「出身大学」「○○大学出身」「出身を問わず」などの学歴・募集条件の文脈、
「宗教学」「設計思想」「チームは何人ですか」「親会社の仕事」「システム障害」などの正当な語は除外しています。
語の追加・除外はテスト（`interview_axis_review_test.go` の正例・負例の表）で固定してください。
質問の記録は、質問キューの文（定型）を、差し替えたときだけ実際に聞いた文へ更新します。
LLM が言い回しを調整した通常の質問文までは保存しません（段階1では見送り）。

## 採点には使わない

`interview_report.go` と `UpdateScoresFromInterviewReport` は人物像・軸を参照しません
（#2123: 同じ回答を企業文脈あり・なしで採点して有意差を出さない条件）。人物像は質問の選択にだけ使います。
テストで、(1) レポートのプロンプトと採点コードが軸を参照しないこと（`TestReportPromptIsIndependentOfAxes`）、
(2) 軸あり・軸なしの2セッションで、レポート生成に渡る入力と保存されるレポートが同一で、軸に由来する文字列
（人物像・axis 等）が現れないこと（`TestReportInputIsIdenticalWithAndWithoutAxes`）を確認しています。

## 守っている制約

- 面接中に Web 検索・企業調査の LLM 呼び出しを足さない（追加の LLM 呼び出しは追質問の既存の1回だけ。
  差別質問の再生成は面接官の返答に限った1回）。
- start-turn / turn / report のレスポンス形は変えない。
- スキーマ変更は `Backend/migrations/20261114004733_add_interview_question_target_axis` の up/down。
