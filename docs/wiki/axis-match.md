# 10カテゴリのスコアと軸別のマッチの可視化（SOCAIAGENT-611 / #2026）

推薦の一覧は「噛み合った軸」を1行出すだけで、自分のどの傾向がどの企業要件に効いたかが分からなかった。
自己理解のために、自分の10カテゴリのスコアと、推薦1件ごとの軸別の内訳を見せる。
**推薦の順位は変えない**。#350（AI の成果を誇張しない）に沿い、控えめに見せる。

## 画面（`/results`）

- **あなたの10の傾向**: 診断のスコア（`GET /api/chat/scores`）を10軸の固定の並びで、数値と細い棒で出す。測れていない軸は「未計測」。高い・低いに良し悪しは無いので、色分けや順位付けはしない
- **軸ごとの内訳を見る**（各企業の行）: 開いたときだけ `GET /api/chat/matches/:id/axes` を取りに行き、次を出す
  - 合っている点（強み）・補うと伝わりやすくなる点（それぞれ3件まで）
  - 企業が重視しているのに、まだ測れていない軸
  - 10軸の表（あなた・企業の重視度・一致度）。狭い画面では線の列を省く
  - 「スコアは AI との対話から推定した参考値、企業の重視度は企業の情報をもとにした目安で、推薦の順位を決めるものではない」の注記
- 行全体は企業詳細を開くので、内訳の中のクリック・キー操作は行へ伝えない

## API

`GET /api/chat/matches/:id/axes`（`id` は推薦の `match_id`）

- 本人の推薦だけ。他人の推薦・存在しない推薦・企業のプロファイルが無い推薦は 404（ID の有無を探らせない）
- `axes`: 10軸ごとに `user_score`（測れていなければ null）・`company_weight`・`match`
- スコアは推薦の計算（`CalculateMatching`）と同じく、その診断のスコアに適性検査を合流させたもの。一致度も同じ式（`CalculateCategoryMatch` = 100 − 差）で、今のスコアから計算し直す

## 言葉にする規則（AI は使わない）

毎回同じ説明になり、誇張しないよう、決まった規則で作る（`matching.BuildAxisBreakdown`）。

| 種類 | 条件 | 並び |
|---|---|---|
| 合っている点 | あなたも企業も 60 以上で、差が 15 以内 | 一致度の高い順、3件まで |
| 補うと伝わりやすくなる点 | 企業が 60 以上で、あなたが 20 以上下回る | 差の大きい順、3件まで |
| まだ測れていない軸 | 企業が 60 以上で、あなたのスコアが無い | 軸の並び |

あなたが企業を上回っている軸は、補う点にも強みにも挙げない（「足りない」と言うことではないため）。
