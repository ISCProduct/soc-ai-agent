# アプリ内通知（#2033）

締切・選考結果・スカウト・先生の案内といった個人宛のイベントを、1か所に集める。
学生の画面の右上にベルと未読バッジを出し、ホームのお知らせ（`NoticeStack`）にも未読を出す。

## 通知を出すとき

| 種類（kind） | いつ | 遷移先 | 二重通知の防止（dedupe_key） |
|---|---|---|---|
| `application` | 学校・企業が選考ステータスを変えたとき（書類選考開始・書類通過・面接予定・面接中・内定・不採用）。学生が自分で変えたとき（応募・辞退・承諾）は出さない | `/applications` | `application:<応募ID>:<ステータス>` |
| `scout` | 企業がスカウトを送ったとき | `/scout` | `scout:<スカウトID>` |
| `guidance` | 先生が案内を出したとき | `/` | `guidance:<案内ID>` |
| `deadline` | 予定（`schedule_events`）の24時間前から。1時間ごとの定期処理で拾う。タイトルが空なら会社名と選考段階を見出しにする | `/schedule` | `schedule:<予定ID>:<予定日時>`（日時を変えたら改めて出す） |

- 通知の作成は本来の処理の付け足しなので、失敗しても本来の処理（応募の更新・スカウトの送信など）は止めず、ログだけ残す
- スカウトの通知はメールより先に作る（メール送信が応答しないと通知まで届かなくなるため）
- 退会ユーザーの物理削除（`hardDeleteUserData`）で通知も消す（先生の案内文や企業名を含むため。`users` への FK は無い）
- 見出しは200文字、本文は1000文字で切り詰める

## API（学生）

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/notifications?limit=&before_id=` | 自分の通知を新しい順に（最大50件）。未読の件数も返す。`unread=1&exclude_kind=guidance` で未読だけ（種類を除いて）返す |
| GET | `/api/notifications/unread-count` | 未読の件数（ベルのバッジ用） |
| POST | `/api/notifications/:id/read` | 1件を既読に。他人の通知や存在しない通知は 404、既読済みは 204 |
| POST | `/api/notifications/read-all` | 未読をすべて既読に |

宛先は `EchoUserAuth`（`X-User-Token`）から決め、`user_id` はクエリや本文から受け取らない。リポジトリのどの操作も `user_id` で絞る。

## 画面

- ベル（`components/NotificationBell.tsx`）: 学生の画面（下のナビと同じ範囲）で、ログイン中だけ右上に固定で出す。AI 面接の本番中と管理者には出さない。未読の件数は60秒ごと（タブが表に出ているとき）とフォーカス時に見直す
- 通知を開くと既読にして、アプリ内のパスだけに移動する（外部 URL へは飛ばさない）
- ベルの一覧は20件ずつで、「さらに読み込む」で古い通知を続けて読める
- ホーム: 未読の通知を `NoticeStack` に並べる（サーバーで未読だけを取る）。先生の案内は既存の案内として出ているので除く。取得や既読に失敗したら、エラーと再読み込みを出す
- ベルとホームは別に一覧を持つので、片方で既読にしたら `app-notifications-changed` イベントでもう片方も取り直す
