# 面接レポートの質問カテゴリ別の評価（SOCAIAGENT-610 / #2025）

面接レポートの評価はルーブリック5軸（論理性・具体性・主体性・コミュニケーション力・積極性）だけで、
どの種類の質問が弱いかが分からなかった。質問の種類ごとに点数と弱点を出し、次の練習につなげる。

## 生成（Backend）

- **OpenAI の呼び出しは増やさない**。既存のレポート生成（`generateReportPayload`、1回の `ChatCompletionWithSchema`）の
  出力に `category_breakdown` を足しただけ
- LLM は面接官の各質問を次のカテゴリに分け、実際に聞かれたカテゴリだけを、ルーブリックと同じ 0〜5 で採点する。
  あわせて足りなかった点（`weakness`）と次に練習すること（`practice`）を1文ずつ書く
  - 自己紹介・志望動機 / 職務経験・実績 / 強み・弱み / キャリアビジョン / 逆質問（面接の進め方 `interviewTopics` と同じ）
  - 企業別の質問（企業から指定された質問・企業研究に基づく質問）
- カテゴリはスキーマの `enum` で縛り、保存前に `SanitizeCategoryBreakdown` で次を捨てる:
  知らないカテゴリ・0〜5 の範囲外・同じカテゴリの2件目。文が両方空でも、点数が範囲内なら行は残す（低い種類を比較から消さない。空の文は画面に出さない）。文は200字を超えたら、省略記号を含めて200字で切る。並びはカテゴリの定義順
- ルーブリックのスコアが不正で捨てた場合（#795）も、カテゴリ別の評価は別に検証しているので残す
- 保存先は `interview_reports.category_breakdown_json`（JSON、migration `20261120113320_interview_report_category_breakdown`）。
  内訳が1件も残らなければ NULL
- 学生に返す（`GET /api/interviews/{id}` の `report.category_breakdown_json`）。教員専用の情報ではない

## 画面

- 面接のレポート（`InterviewSummary`）の「改善点」の次に「質問の種類ごとの評価」を出す
  - 種類ごとに「N / 5」・足りなかった点・次の練習
  - いちばん点の低い種類に「次に練習したい」の印（全部同じ点のとき、いちばん低くても4点以上のときは付けない）
  - 1種類あたりの質問は1〜2問と少ないため、点数は目安であることを画面に書く
  - 「AI が回答を 0〜5 で評価した参考値」の注記
- この列を足す前のレポート（NULL）や、壊れた JSON では欄ごと出さない

## 制約

- 発話と質問は紐づいていない（`interview_utterances` に質問 ID が無い）ので、カテゴリ分けは LLM が面接ログから行う。
  分け方が人の感覚とずれることはある
- カテゴリ別の点数は `user_weight_scores` には反映しない（マッチングには使わない）
