# 教員と学生の相談（#2028）

教員の案内は一方向だったので、学生が返信・質問できるようにする。

## しくみ

- 案内（`teacher_student_guidances`）を1つのスレッドとし、発言を `guidance_messages`（`Backend/migrations/20261123065700_guidance_messages.up.sql`）に積む
- 学生からの質問は、種類 `question` の案内（`teacher_user_id = 0`）として作り、最初の発言も `guidance_messages` に入れる。担当校の先生なら誰でも答えられる
- `read_at` は相手側が読んだ日時。スレッドを開くと、**その応答に含めた発言の ID だけ**が既読になる（取得のあとに届いた発言や、採番は先でもコミットが遅れて取得に含まれなかった発言は未読のまま）
- 先生が返信するときは、画面に出ていた発言の ID の一覧（`seen_message_ids`）のうち学生の未読の発言を、返信と同じトランザクションで既読にする。「ID が N 以下」の範囲では決めない（画面に出ていなかった発言まで既読になるため）
- 発言を保存するときは、先に親の案内の行をロックし、無ければ 404 にする（`guidance_messages` に外部キーが無いので、退会者の削除と重なっても親の無い発言を残さない）
- 質問を作るときは学生の行をロックしたあとに退会を確かめ、退会済みなら作らない（403。学校の確認で退会済みと分かったときと同じ）
- 学生が返信したスレッドは、閉じていても開き直す（先生の返答を見落とさないように）
- 本文は前後の空白を除いて1000文字まで。文字数は Unicode のコードポイントで数える（画面も `Array.from` で同じ数え方にする）
- 発言の保存のあとにスレッドの読み直しだけ失敗したら、201 で `stale: true` と保存した発言（実際の ID と作成日時）を返す。画面は送信成功として入力を消し、保存した発言を表示中のスレッドに足してから読み直す。読み直しにも失敗したら、スレッドは残して警告を出す（500 にすると再送で発言が二重になるため）

## 質問の受け付け

- 質問は学生の学校の先生の受信一覧に届く。届け先が無い質問は受け付けない
  - 学生でない（ゲスト・管理者・職員）: 403
  - 学校が未登録、または学校の学園が本人の学園と違う（`SchoolService.EffectiveSchoolID`）: 400
- 先生がまだ1度も答えていない質問は、学生1人あたり5件まで（`teacher.MaxOpenQuestions`）。超えると 429。1人が質問を大量に作って、同じ学校のほかの学生の質問を埋もれさせないため

## API

| 主体 | メソッド | パス | 内容 |
|---|---|---|---|
| 学生 | GET | `/api/user/consultations?limit=&cursor=` | 本人の案内と質問の一覧（新しく動いた順。閉じた案内も含む）。続きは `next_cursor` |
| 学生 | POST | `/api/user/consultations` | 先生への質問のスレッドを作る |
| 学生 | GET | `/api/user/consultations/unread` | スレッドごとの、先生の未読の発言の数 |
| 学生 | GET | `/api/user/consultations/:id` | 本人のスレッド（他人のは 404）。表示した先生の発言を既読にする |
| 学生 | POST | `/api/user/consultations/:id/messages` | 本人のスレッドに返信 |
| 先生 | GET | `/api/admin/teacher/consultations?school_id=&limit=&before_id=` | 受信一覧（担当校スコープ。学生の発言があるスレッドを、最後の発言の新しい順に）。続きは `next_before_id` |
| 先生 | GET | `/api/admin/teacher/consultations/:id` | スレッドを見る（表示した学生の発言を既読にする） |
| 先生 | POST | `/api/admin/teacher/consultations/:id/messages` | 返信（`seen_message_ids` のうち学生の未読の発言を既読にする） |

学生の API は、フロントの同一オリジンの中継（`frontend/app/api/user/consultations/`）を通す。

先生のスレッドの2本は `school_id` を持たないので、コントローラでスレッドの学生の学校と担当校を突き合わせる
（`EnsureAdminSchoolAccessForUser`）。担当校以外は、存在しない ID と同じく **404** にする（他校の相談の ID の有無を探らせない）。

受信一覧は、`ResolveStudentSchool` と同じ条件（学生ロール・管理者でない・ゲストでない・退会していない）の学生に限る。
一覧に出るのに開けない行を作らないため。

GET でスレッドを開くと既読になる（既存の通知と同じく、開いたことを既読とみなす）。

## 退会

学生・先生のどちらとして退会しても、本人が書いた発言と、本人が学生・送信教員である案内のスレッドの発言を消す
（`UserWithdrawalRepository.hardDeleteUserData`。`guidance_messages` には案内・ユーザーへの外部キーが無いので、案内より先に明示的に消す）。

## 画面

- 学生: `/consultations`（質問の投稿、やり取りの一覧と未読の印、スレッドのダイアログ）。ホームの案内の「先生に返信する」と、プロフィールのカードから開く
- 先生: `/admin/consultations`（受信一覧と未読の印、スレッドのダイアログ）。管理画面の「教員業務」から開く
- どちらの一覧も「さらに読み込む」で続きを取る。絞り込み（学校）を切り替えたときは、前の条件の遅い応答で表示を上書きしない

## ロールバック

`20261123065700_guidance_messages.down.sql` は `guidance_messages` を消す前に、学生の質問（`kind = 'question'`）の親の行を
閉じる（`dismissed_at` を入れる）。行は消さない（学生の質問の本文を残す）。旧版の `ListActiveByStudent` は種類で除外しないので、
閉じないと学生の質問が「先生からの案内」としてホームに出るため。もう一度 up すると、閉じた質問は学生の相談一覧には出るが、
ホームの案内（閉じていないもの）には出ない（質問はもともとホームに出さない）。
