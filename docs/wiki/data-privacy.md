# データプライバシー設計

## 概要

集合知レコメンド（#205）および退会・個人データ削除（#613）におけるプライバシー設計方針をまとめます。

---

## 退会・ユーザーデータ削除（#613）

### 方針

退会時は **論理削除（ソフトデリート）** とし、関連 DB 行および S3 オブジェクトは **12ヶ月保持**します。保持期間中はログイン・本人 API・管理者からの動画等の閲覧を不可にします。期間経過後に物理削除（ハードデリート）します。再計算前のスコア控えも、スコア本体と同じ日に消します。

### API

| 操作 | メソッド / パス | 認証 | 動作 |
|------|-----------------|------|------|
| 本人退会 | `DELETE /api/users/me` | `X-User-Token`（JWT） | 論理削除 |
| 本人退会（互換） | `DELETE /api/auth/account` | 同上 | 同上 |
| 管理者退会 | `DELETE /api/admin/users/:id` | `X-Admin-Email` / `X-Admin-Token` | 論理削除 |
| 期限切れパージ | `POST /api/admin/users/purge-expired` | 同上 | 保持期間経過分の物理削除（起動時/日次バッチでも実行） |

### 退会直後（論理削除）

| 項目 | 内容 |
|------|------|
| `users.withdrawn_at` | 退会日時を記録 |
| `withdrawn_users` | メールハッシュ・マスク・S3キー一覧・`purge_after`（+12ヶ月）を記録 |
| メール | `withdrawn+{id}@deleted.invalid` にスクランブル（同一アドレスでの再登録を許可） |
| 認証情報 | パスワード / OAuth / 管理者権限をクリア |
| 関連 DB・S3 | **残す**（閲覧不可） |
| ログイン / JWT API | 拒否 |
| 管理者の面接動画 Presign 等 | 所有者退会中は拒否 |

### 保持期間経過後（物理削除）

| レイヤー | 内容 |
|---------|------|
| DB | チャット・スコア・応募・面接セッション/発言/レポート/質問状態/動画メタ・履歴書およびレビュー・GitHub・スケジュール・Google トークン・`user_embeddings` 等 |
| S3 | 退会時に記録した面接動画・履歴書オブジェクトキー |
| 集合知 | 当該ユーザーの `anonymous_user_id`（決定論的 SHA-256）に一致する `collective_insight_logs` |
| 学習利用の同意の履歴 | 当該ユーザーの `training_consent_events`（#2168。下記「学習利用の同意」） |
| ベクトルストア（Chroma） | **ユーザー単位の埋め込みは存在しない**ため対象外 |

S3 削除は DB コミット後の best-effort です。失敗時は監査ログ `metadata.s3_errors` に記録します。

### 使われなくなったゲストの掃除（SOCAIAGENT-689）

最後に使ってから7日たったゲスト（リフレッシュトークンの最終発行で判定。トークンが無ければ作成日時）を、日次ジョブが上と同じ経路で論理退会させます。データは通常の退会と同じく **12ヶ月保持**し、その後に物理削除します。保持期間は `WithdrawalRetentionMonths`（`Backend/internal/services/auth/user_deletion_service.go`）です。

- 対象: ゲスト・管理者でない・未退会。1回 500 件まで
- 一覧を取ったあとで本登録した・使ったゲストは、退会のトランザクションの中で確かめ直して対象から外します

### 監査ログ

| Action | 実行者 |
|--------|--------|
| `user.self_withdraw` | 本人 |
| `user.admin_withdraw` | 管理者（`X-Admin-Email`） |
| `user.guest_expire` | システム（使われなくなったゲストの掃除） |
| `user.purge` | システム（バッチ / 管理者パージ） |

`GET /api/admin/audit-logs` で確認できます。

## 匿名化方式

### userIDのハッシュ化

個人を特定できないよう、`CollectiveInsightLog` に保存する `anonymous_user_id` は以下の形式でSHA-256ハッシュ化します:

```
anonymous_user_id = SHA-256("user:{userID}:collective")
```

**特徴:**
- 元のuserIDは復元不可能
- 同一ユーザーのログは一貫したハッシュで紐付け可能（集計に必要）
- ハッシュ化には固定のプレフィックス・サフィックスを使用し、他のシステムのハッシュと衝突しにくい設計
- 退会後の物理削除時に同一ハッシュのログを削除する（#613）

## 外部の AI へ送る前の伏字（piimask）

学生の文章を外部の LLM・API へ送るときは、送る前に、個人を特定できる語を伏字にする（`Backend/internal/services/piimask`）。
学習データの書き出し用の `training/masking` を土台に、LLM へ送る用途に合わせている。

- **対象の項目**: 氏名・学校名・メール・電話・住所（`masking` の規則）に、生年月日・郵便番号・URL・SNS のアカウント名・本人に結びつく番号（学籍番号・マイナンバーなど）を足す。
  氏名・学校名・メールは、その学生の登録情報（`users`）から辞書を作って照合する。メールのローカル部（`taro.yamada`）から、ローマ字の氏名の候補も取る。
  電話はハイフンの前後の空白、住所は都道府県の省略、メールは `(at)` 表記、URL はスキームなし（`github.com/…`）、生年月日は漢数字・`04/01/1999`・`（22歳）` も拾う。
- **伏字にしないもの**: 応募先の企業名（レビューに必要な公開情報）、日が無い年月（学歴・職歴）、数字、都道府県だけの地名。
- **連絡先の欄**: 履歴書の「氏名・ふりがな・生年月日・住所・電話・メール・性別・年齢・写真」の見出しで始まる短い行は、行ごと送らない。OCR が見出しと値を別のブロックに分けたときは、見出しだけの行の次の短いブロック（値）も除く（辞書にない書き方のふりがな・ローマ字を残さないため）。住所・電話・メールの欄の行の次に、番地・建物名・電話やメールの続きが来たときは、続けて最大2ブロックを除く（年月日で始まる行は学歴・職歴なので残す）。「…@」で終わるブロックの次の先頭のドメインも伏字にする。OCR が数字の間に空白を入れた電話番号も拾う。
- **失敗したら送らない**: 登録情報を読めない・伏字の準備ができないときは、本文を外へ送らず、利用者へ「安全に処理できなかったため、もう一度お試しください」と返す。
  登録情報の読み取りを注入していない（未ログインなど）ときも、規則での伏字は必ず行う。
- **履歴書**: 外へ送れるのは伏字済みのブロック（`llmBlocks`）だけ。元のブロックを渡す呼び出しは、コンパイルが通らない。
  DB に保存する本文と注釈PDFの位置は元のまま。指摘は `block_index` で元のブロックに対応づく（伏字にしても位置は変わらない）。
- **ES 添削・リライト**: 唯一の生成経路 `postESReview` で伏字にする。
- **チャット診断**: 入口（`ChatService.ProcessChat`・`RecalculateChatSession`）で `openai.WithInputGuard` を付ける。
  外部 AI 呼び出し（回答の評価・妥当性判定・質問生成・要約・埋め込み）のユーザー入力は、送る直前に、`openai.Client` の入口で伏字になる。
  固定のシステムプロンプトにはかけない。ガードを付けていない呼び出し（企業調査など、学生の文章を含まないもの）は変わらない。
  ガードを作れないときは `ErrInputGuardFailed` で、何も送らない。新しい経路を足すときは、学生の文章を送るなら入口でガードを付ける。
- **面接**: `Turn`・`StartTurn`・フレーズ提案・レポート生成の入口でガードを付ける。面接官の応答の呼び出し（`ChatInterview`）は、発話の履歴を伏字にして送る。
  **氏名の呼びかけ**: 面接官のシステムプロンプトに登録氏名は入れない。氏名では呼ばず「あなた」などで呼びかける指示だけを渡す。AI の応答に残った伏字の記号（`<NAME>` など）は、表示・読み上げの前に `piimask.StripTokens` で取り除く。
  **対象外（意図的）**: 音声そのもの（文字起こし前の音声は伏字にできない。音声は文字起こしのため OpenAI へ送る方針。学生が声で名乗った氏名は音声に残るため、同意文言とベンダー側の保存設定で担保する）。
  レポートの根拠の照合は元の発話と比べるため、伏字になった氏名を含む引用は照合に合わないことがある。
- **RAG（Python）経由で OpenAI へ送る経路**: 学生の文章を RAG へ渡すのは、履歴書レビュー・ES 添削・学生の意味検索の3つ。履歴書レビューと ES 添削は、Go 側で伏字にした本文だけを RAG へ送る。意味検索のインデックス（自己PR・希望勤務地などの自由記述）も、`StudentIndexSyncer` が送る前に伏字にし、伏字にできなければ送らない。RAG 自体は伏字を行わないので、RAG へ学生の文章を送る処理を足すときは、Go 側で伏字にしてから渡す。企業情報だけを扱う経路（`/company/*`・`/vector/reembed`）は対象外。
- **分析・診断品質**: `BuildAnalysisSummary`・`RunDiagnosisQuality` で、直近の発言・会話の抜粋を伏字にして送る（`SubjectReader` を注入）。
- **対象外**: マッチング理由の生成（スコアと企業情報だけを送り、学生の文章は送らない）。

**限界**: 辞書にない氏名（本文に出てくる第三者の名前など）、本文中のふりがな・カタカナの氏名（漢字で登録した氏名から読みは導けない）、番地の無い町名、年齢だけの記述、文脈から人が分かる記述は残る。登録した姓が企業名の一部（`田中製作所`）に一致すると、そこも伏字になる（過剰に伏字になる方向）。送る量を必要な範囲に絞ること、
ベンダー側の取り扱いの確認と併用する。項目を足すときは `piimask_test.go` に合成データの例を足す（実在の個人情報は使わない）。

## 同意管理

### ユーザー同意フラグ

`users.allow_collective_insight` フラグ（デフォルト: `true`）で管理します。

| フラグ | 動作 |
|-------|------|
| `true`（デフォルト） | 行動ログを匿名化して記録 |
| `false` | 行動ログは一切記録しない |

### 同意変更API

```
PUT /api/collective-insights/consent
{
  "user_id": 123,
  "allow": false
}
```

**注意:** 同意取り消し後も、退会しない限り過去の匿名ログは残ります。物理削除時は上記のとおりハッシュ一致分を削除します。

### 推薦への「合う／合わない」（SOCAIAGENT-670）

推薦の精度を、実際の学生の判断で測るために、推薦 1 件ごとの「合う／合わない」を記録する（`user_match_feedbacks`）。

- **記録する内容**: 本人の ID、推薦の ID、判定（`fit` / `unfit`）、押した時点の適合度・ずれる軸・職種の加点の写し。**自由記述は持たない**。企業名・氏名など個人を識別できる文字列は、この表に保存しない。
- **使い道**: 「参考」の判定や職種の加点が当たっているかの評価（集計コマンド `cmd/profile-distribution`）。**AI の学習データには使わない**（学習への利用は、同意のあるデータだけを対象にした別の経路）。
- **退会**: 退会の物理削除（`hardDeleteUserData`）で、推薦より先に明示的に消す。推薦への外部キー（CASCADE）は、消し忘れの保険。
- **本人以外**: 他人の推薦には付けられない（403）。本人の判定は、本人の推薦にだけ返す。

### 学習利用の同意（#2167 / #2168）

面接データを軽量の採点モデル（#1834）の学習に使ってよいかの同意です。集合知の同意とは別のフラグで、**既定は「同意しない」（opt-in）**です。

| 項目 | 内容 |
|------|------|
| 現在値 | `users.allow_training_use`（既定 `0`） |
| 変更の履歴 | `training_consent_events`。変更のたびに、値の更新と同じトランザクションで1行追加する（更新・削除はしない）。どの文言の版（`consent_text_version`）に対する操作か、いつ（DB の `NOW(3)`）を残す |
| 文言の版 | `models.TrainingConsentTextVersion`。同意の画面（`frontend/components/profile/TrainingConsentCard.tsx`）の文言を変えたら上げる |
| 記録を始める前からの同意 | 版を `legacy-before-history` にした行をマイグレーションで作った。`created_at` はマイグレーションの適用時刻で、同意した日時ではない |
| API | `GET` / `PUT /api/user/training-consent`（[API リファレンス](./api-reference.md#学習利用の同意2167--2168)） |
| 学習データの書き出し | 同意あり・未退会・学生（ゲスト以外）だけを書き出す。手順は [採点モデルの学習データの書き出し](./scorer-training-data.md) |

**保持の方針:** 同意の履歴は、退会後の物理削除（パージ）で**ほかの個人データと一緒に消します**。パージの後は「いつ・どの文言に同意したか」の証跡は残りません。退会した人のデータは学習に使わないので、同意の証跡を個人データより長く残す理由が無いためです。

**撤回・退会と書き出し済みのデータ:** 同意を取り消した学生と退会した学生の書き出し済みのデータ（S3）は、書き出しのたびと毎日の定期実行の削除で、すべての回から消します。退会した学生は、パージのときにも消します（[書き出し済みのデータの削除](./scorer-training-data.md#書き出し済みのデータの削除同意の取り消し退会)）。本番での書き出しは、[運用ゲート](./scorer-training-data.md#本番で実行する前に揃えるもの運用ゲート)が揃ってから行います。

**同意の文言の版と、動画の扱い:**

| 版 | 対象 |
|---|---|
| `2026-11-11` | 発話とスコア |
| `2026-11-18` | 発話・スコア・**録画した動画** |

- 動画を学習に使う処理を作るときは、**版が `2026-11-18` 以降の同意の人だけ**を対象にする。旧版（`2026-11-11`）に同意した人は、動画を含む内容には同意していない。
- 動画の顔・声は伏字にできない。同意した人だけを使い、オフにしたら書き出し済みの分も消す。
- 同意していない人の動画は、アカウントが有効な間保管し、退会後12ヶ月で削除する（退会処理が動画の保存先も消す）。

## 記録するデータの範囲

`CollectiveInsightLog` に保存されるデータ:

| フィールド | 内容 | 個人特定可能性 |
|----------|------|--------------|
| `anonymous_user_id` | SHA-256ハッシュ | 不可 |
| `company_id` | 企業ID（整数） | 不可 |
| `action_type` | viewed / applied / passed / rejected | 不可 |
| `score_snapshot` | 応募時点のカテゴリ別スコア、総合マッチ度、軸別マッチ度（JSON。設問本文は含めない） | 不可（スコアのみ） |
| `application_status_events` | 選考ステータスの遷移と変更者のロール | 退会時にユーザー単位で削除 |
| `created_at` | タイムスタンプ | 単独では不可 |

**記録しないデータ:**
- 氏名・メールアドレス・電話番号
- セッションID・IPアドレス
- 具体的な応募内容・面接内容

## 集合知レコメンドで使用するデータ

レコメンド生成時には以下のみを使用します:

1. 匿名ユーザーハッシュの一覧（類似度計算用）
2. 各ハッシュに紐づく企業IDと行動タイプ（通過/応募）
3. スコアスナップショット（コサイン類似度計算用）

個人の氏名・連絡先・具体的な応募内容は使用しません。

## データ保持ポリシー

| データ | 保持期間 | 備考 |
|-------|----------|------|
| ユーザー PII（プロフィール・チャット・面接・履歴書等） | 退会後 12 ヶ月 | 退会は論理削除。期間中は閲覧・ログイン不可（#613、SOCAIAGENT-633） |
| 面接動画・履歴書ファイル（S3） | 退会後 12 ヶ月 | 期間中は Presign / ダウンロード拒否。経過後にオブジェクト削除 |
| `user_score_recalculation_snapshots` | 退会後 12 ヶ月 | 再計算前のスコア控え。スコア本体と同じパージで消す |
| `withdrawn_users` | パージ後も行を残す（`purged_at`） | 監査・再登録衝突調査用（メールはハッシュ/マスクのみ） |
| `collective_insight_logs` | 物理削除時に当該ハッシュ分を削除 / 残分は最大2年推奨 | バッチで古い行を削除可 |
| `training_consent_events`（学習利用の同意の履歴） | 退会後 12 ヶ月（パージで削除） | 退会していない間は消さない |
| 採点モデルの学習データ（S3 の書き出し） | 1年（予定。infra で設定） | 撤回・退会で消す（書き出しのたび・毎日の削除・パージ）。手順は [学習データの書き出し](./scorer-training-data.md) |
| `training_scorer_export_runs`（書き出しの監査ログ） | 無期限 | 件数と出力先だけで、個人を特定するものは持たない |
| `anonymized_behavior_summaries` | 無期限 | 集計済みのため個人特定不可 |
| `score_calibration_weights` | 無期限 | バージョン管理で履歴として保持 |
| `audit_logs`（退会・パージ記録） | 無期限（推奨） | 法令対応・インシデント調査用。マスク済みメールが metadata に残る点に注意 |
| STT評価用の発話音声（音声R&D Task 6） | **最長90日**（評価完了で即削除） | 個別同意が前提。本番S3とは別バケット。詳細は下記 |

### STT評価用に収集する発話音声（音声R&D Task 6）

音声認識の品質を実発話で検証するために、学生の音声を収集する計画がある
（`docs/research/interview-audio-eval/CLAUDE_HANDOFF.md` Task 6）。
**通常の面接データとは別枠**として扱う。面接の音声は本人のためのものだが、
評価用に取る音声は**開発側が繰り返し聞く**ため、同じ扱いにはできない。

収集を始める前に次を満たすこと。

| 項目 | 決めたこと |
| --- | --- |
| 同意 | **収集ごとに個別の同意**を取る。利用規約への一括同意で代替しない |
| 同意の内容 | 「開発者が音声を聞くこと」「保存期間」「いつでも削除を依頼できること」を明示する |
| 対象 | 同意した学生の発話のみ。**面接本番の録音を後から流用しない** |
| 保存場所 | 本番の S3 バケットとは分ける。本番データと混ざると削除漏れが起きる |
| 保存期間 | **最長90日**。評価が終わったら期間内でも消す |
| アクセス権 | 音声R&Dの担当者のみ。**一覧・ダウンロードの操作をログに残す** |
| 削除方法 | 本人からの依頼で個別削除できること。依頼窓口を同意時に伝える |
| 撤回 | 同意の撤回をいつでも受け付け、撤回後は残っている音声をすべて削除する |
| 書き起こし | 発話本文もPIIとして扱う。**リポジトリへコミットしない**（`.gitignore` 済み） |

**この表が埋まるまで収集を始めない。** 合成音声での評価
（`RESULTS_synthetic.md` / `RESULTS_stt_hints.md`）は実発話の代わりにならないが、
同意と削除手順が決まらないうちに実発話を集める方がリスクが大きい。

サンプル数は「多いほどよい」ではなく、**評価に必要な最小限**にすること。
`CLAUDE_HANDOFF.md` が挙げる条件（静かな部屋 / 雑音 / 反響 / 小声 / 早口 /
言い淀み × 複数端末）を1つずつ埋める設計にして、無制限に集めない。

### AI出力評価用のゴールデンセット（#1525）

ES添削・履歴書レビュー・面接レポート・チャット診断の回答評価の品質を測る評価ハーネス
（`Backend/cmd/aibench` / `docs/research/ai-eval/`）が使う入力セット。

| 項目 | 決めたこと |
| --- | --- |
| コミットするデータ | **合成データのみ**。氏名は「学生A」、企業・学校名は「株式会社サンプル○○」等の架空名で統一 |
| 実データ | **リポジトリに置かない**。匿名化済みでも `docs/research/ai-eval/` には置かない |
| 実データで測るとき | マニフェストと結果JSONの両方をリポジトリ外（例: `~/ai-eval-private/`）に置く。`-manifest` / `-out` は任意のパスを受け付ける |
| 匿名化の範囲 | 氏名・学校名・企業名・連絡先・生年月日に加え、**エピソード中の固有名詞**（部活名・大会名・アルバイト先の店名）も置き換える。個人を特定しうるため |
| 結果の共有 | 実データで測った数字は「実データ / 非公開マニフェスト」と明記する。合成データの数字と混ぜて比較しない |
| 出力本文 | LLM の出力（添削文・レポート本文）は結果JSONにのみ残し、ターミナル・CIログへ出さない |

STT評価用の音声（上記）と違い、こちらは**収集しない**設計にしてある。
合成データで弁別力・破損率・再現性は測れるため、実データの収集を前提にしない。
ラベルの付け方と基準は `docs/research/ai-eval/README.md` を参照。

## ログの個人情報の扱い

ログ・エラー文に、学生の入力（チャットの回答・面接の発話・履歴書や ES の本文・プロンプト全文）とメールアドレス・電話番号を出さない。出すのは、ID・件数・文字数・結果コードだけ。

守り方は3段。

1. **書き方**: 学生の入力は `logsafe.Chars(text)`（文字数）で出し、メールは `logsafe.MaskEmail` / `MaskEmails`（`t***@example.com`）で伏せる。
2. **検査（`internal/logpolicy`）**: `log.*` / `slog.*` の呼び出しの引数に、名前の最後の単語が `email` `phone` `address` `answer` `message` `text` `content` `body` `prompt` `utterance` `transcript` `to` `input` などの値を渡すと、`go test` が落ちる（CI の Go Unit Tests）。`internal/` と `cmd/` の全体が対象。`import stdlog "log"` の別名、`log.Default().Printf`、名前が `log` / `logger` で終わる値のメソッド（`s.logger.Info`）も見る。
   出してよい理由があるときだけ、その行の**コメントに** `// logpolicy:ok 理由` を書く（理由が無い目印、文字列の中の目印は許可にならない。企業情報・料金のアラート本文など、学生の入力を含まないもの）。`reason` は、コード（理由の種別）と自由記述の両方に使われ名前で区別できないため、検査の対象外。自由記述は `answer` / `text` などの名前で運ぶこと。
3. **出力直前の伏字（`internal/logger/redact.go`）**: `slog` のハンドラが、メッセージと文字列・error・`String()` を持つ値・グループの値の、メールアドレスと電話番号を `<EMAIL>` / `<PHONE>` にする。`slog.SetDefault` 後は標準の `log.Printf` も同じハンドラを通る。
   電話番号は、ID・UUID・sha・16進・小数・パスの断片を誤って伏字にしないよう、前後が英数字・`.`・`-`・`_`・`/` のものと、「0.」「0-」で始まるものを除く（学習データ用の規則に、ログ用の条件を足している）。氏名・住所は規則では見分けられないので対象外（1・2 で守る）。構造体・マップの値は中身を見ない。`String()` / `Error()` が panic する値（nil ポインタ）は、元の値のまま渡す。

## 学習データの書き出しの条件

管理者向けの書き出し（`/api/admin/training/export`・`/stats`）は、次の条件に合う学生のデータだけを数え、書き出す。条件は `TrainingExportRepository.trainingConsentedUserIDs` に1か所だけ書き、すべての問い合わせが通る。

- 学習利用に同意済み（`users.allow_training_use = 1`）
- 未退会（`withdrawn_at IS NULL`。退会の猶予期間中は論理削除でフラグが 1 のまま残るため、フラグだけでは判定しない）
- 学生ロール・非ゲスト

発話の取り出しは、一覧を取ったあとに同意を取り消した人の発話を拾わないよう、セッション単位でも条件を付け直す。条件を変えたら、`training_export_repository_test.go` の期待 SQL も合わせる（外すとテストが落ちる）。
