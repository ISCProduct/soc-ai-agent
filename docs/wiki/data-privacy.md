# データプライバシー設計

## 概要

集合知レコメンド（#205）および退会・個人データ削除（#613）におけるプライバシー設計方針をまとめます。

---

## 退会・ユーザーデータ削除（#613）

### 方針

退会時は **論理削除（ソフトデリート）** とし、関連 DB 行および S3 オブジェクトは **30日間保持**します。保持期間中はログイン・本人 API・管理者からの動画等の閲覧を不可にします。期間経過後に物理削除（ハードデリート）します。

### API

| 操作 | メソッド / パス | 認証 | 動作 |
|------|-----------------|------|------|
| 本人退会 | `DELETE /api/users/me` | `X-User-Token`（JWT） | 論理削除 |
| 本人退会（互換） | `DELETE /api/auth/account` | 同上 | 同上 |
| 管理者退会 | `DELETE /api/admin/users/:id` | `X-Admin-Email` / `X-Admin-Token` | 論理削除 |
| 期限切れパージ | `POST /api/admin/users/purge-expired` | 同上 | 保持期間経過分の物理削除（起動時/日次バッチでも実行） |

### 退会直後（論理削除）

| 項目 | 内容 |
|------|------|
| `users.withdrawn_at` | 退会日時を記録 |
| `withdrawn_users` | メールハッシュ・マスク・S3キー一覧・`purge_after`（+30日）を記録 |
| メール | `withdrawn+{id}@deleted.invalid` にスクランブル（同一アドレスでの再登録を許可） |
| 認証情報 | パスワード / OAuth / 管理者権限をクリア |
| 関連 DB・S3 | **残す**（閲覧不可） |
| ログイン / JWT API | 拒否 |
| 管理者の面接動画 Presign 等 | 所有者退会中は拒否 |

### 保持期間経過後（物理削除）

| レイヤー | 内容 |
|---------|------|
| DB | チャット・スコア・応募・面接セッション/発言/レポート/質問状態/動画メタ・履歴書およびレビュー・GitHub・スケジュール・Google トークン・`user_embeddings` 等 |
| S3 | 退会時に記録した面接動画・履歴書オブジェクトキー |
| 集合知 | 当該ユーザーの `anonymous_user_id`（決定論的 SHA-256）に一致する `collective_insight_logs` |
| ベクトルストア（Chroma） | **ユーザー単位の埋め込みは存在しない**ため対象外 |

S3 削除は DB コミット後の best-effort です。失敗時は監査ログ `metadata.s3_errors` に記録します。

### 監査ログ

| Action | 実行者 |
|--------|--------|
| `user.self_withdraw` | 本人 |
| `user.admin_withdraw` | 管理者（`X-Admin-Email`） |
| `user.purge` | システム（バッチ / 管理者パージ） |

`GET /api/admin/audit-logs` で確認できます。

## 匿名化方式

### userIDのハッシュ化

個人を特定できないよう、`CollectiveInsightLog` に保存する `anonymous_user_id` は以下の形式でSHA-256ハッシュ化します:

```
anonymous_user_id = SHA-256("user:{userID}:collective")
```

**特徴:**
- 元のuserIDは復元不可能
- 同一ユーザーのログは一貫したハッシュで紐付け可能（集計に必要）
- ハッシュ化には固定のプレフィックス・サフィックスを使用し、他のシステムのハッシュと衝突しにくい設計
- 退会後の物理削除時に同一ハッシュのログを削除する（#613）

## 同意管理

### ユーザー同意フラグ

`users.allow_collective_insight` フラグ（デフォルト: `true`）で管理します。

| フラグ | 動作 |
|-------|------|
| `true`（デフォルト） | 行動ログを匿名化して記録 |
| `false` | 行動ログは一切記録しない |

### 同意変更API

```
PUT /api/collective-insights/consent
{
  "user_id": 123,
  "allow": false
}
```

**注意:** 同意取り消し後も、退会しない限り過去の匿名ログは残ります。物理削除時は上記のとおりハッシュ一致分を削除します。

## 記録するデータの範囲

`CollectiveInsightLog` に保存されるデータ:

| フィールド | 内容 | 個人特定可能性 |
|----------|------|--------------|
| `anonymous_user_id` | SHA-256ハッシュ | 不可 |
| `company_id` | 企業ID（整数） | 不可 |
| `action_type` | viewed / applied / passed / rejected | 不可 |
| `score_snapshot` | カテゴリ別スコア（JSON） | 不可（スコアのみ） |
| `created_at` | タイムスタンプ | 単独では不可 |

**記録しないデータ:**
- 氏名・メールアドレス・電話番号
- セッションID・IPアドレス
- 具体的な応募内容・面接内容

---

## 集合知レコメンドで使用するデータ

レコメンド生成時には以下のみを使用します:

1. 匿名ユーザーハッシュの一覧（類似度計算用）
2. 各ハッシュに紐づく企業IDと行動タイプ（通過/応募）
3. スコアスナップショット（コサイン類似度計算用）

個人の氏名・連絡先・具体的な応募内容は使用しません。

## データ保持ポリシー

| データ | 保持期間 | 備考 |
|-------|----------|------|
| ユーザー PII（プロフィール・チャット・面接・履歴書等） | 退会後 30 日 | 退会は論理削除。期間中は閲覧・ログイン不可（#613） |
| 面接動画・履歴書ファイル（S3） | 退会後 30 日 | 期間中は Presign / ダウンロード拒否。経過後にオブジェクト削除 |
| `withdrawn_users` | パージ後も行を残す（`purged_at`） | 監査・再登録衝突調査用（メールはハッシュ/マスクのみ） |
| `collective_insight_logs` | 物理削除時に当該ハッシュ分を削除 / 残分は最大2年推奨 | バッチで古い行を削除可 |
| `anonymized_behavior_summaries` | 無期限 | 集計済みのため個人特定不可 |
| `score_calibration_weights` | 無期限 | バージョン管理で履歴として保持 |
| `audit_logs`（退会・パージ記録） | 無期限（推奨） | 法令対応・インシデント調査用。マスク済みメールが metadata に残る点に注意 |
| STT評価用の発話音声（音声R&D Task 6） | **最長90日**（評価完了で即削除） | 個別同意が前提。本番S3とは別バケット。詳細は下記 |

### STT評価用に収集する発話音声（音声R&D Task 6）

音声認識の品質を実発話で検証するために、学生の音声を収集する計画がある
（`docs/research/interview-audio-eval/CLAUDE_HANDOFF.md` Task 6）。
**通常の面接データとは別枠**として扱う。面接の音声は本人のためのものだが、
評価用に取る音声は**開発側が繰り返し聞く**ため、同じ扱いにはできない。

収集を始める前に次を満たすこと。

| 項目 | 決めたこと |
| --- | --- |
| 同意 | **収集ごとに個別の同意**を取る。利用規約への一括同意で代替しない |
| 同意の内容 | 「開発者が音声を聞くこと」「保存期間」「いつでも削除を依頼できること」を明示する |
| 対象 | 同意した学生の発話のみ。**面接本番の録音を後から流用しない** |
| 保存場所 | 本番の S3 バケットとは分ける。本番データと混ざると削除漏れが起きる |
| 保存期間 | **最長90日**。評価が終わったら期間内でも消す |
| アクセス権 | 音声R&Dの担当者のみ。**一覧・ダウンロードの操作をログに残す** |
| 削除方法 | 本人からの依頼で個別削除できること。依頼窓口を同意時に伝える |
| 撤回 | 同意の撤回をいつでも受け付け、撤回後は残っている音声をすべて削除する |
| 書き起こし | 発話本文もPIIとして扱う。**リポジトリへコミットしない**（`.gitignore` 済み） |

**この表が埋まるまで収集を始めない。** 合成音声での評価
（`RESULTS_synthetic.md` / `RESULTS_stt_hints.md`）は実発話の代わりにならないが、
同意と削除手順が決まらないうちに実発話を集める方がリスクが大きい。

サンプル数は「多いほどよい」ではなく、**評価に必要な最小限**にすること。
`CLAUDE_HANDOFF.md` が挙げる条件（静かな部屋 / 雑音 / 反響 / 小声 / 早口 /
言い淀み × 複数端末）を1つずつ埋める設計にして、無制限に集めない。

### 古い集合知ログの削除（例）

```sql
DELETE FROM collective_insight_logs
WHERE created_at < DATE_SUB(NOW(), INTERVAL 2 YEAR);
```
