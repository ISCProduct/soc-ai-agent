# 🛡️ カタグルマ・コードレビューガイドライン

カタグルマは保育・教育現場のインフラです。コードの美しさだけでなく、現場の先生が迷わず、安全に、止まることなく使えるかを最優先にレビューします。

## 重点チェック項目

### ドメイン・業務仕様
- 年度の隔離: 取得処理に選択中の年度が考慮され、年度更新時に不整合が起きないか。
- 施設・権限の壁: `facility_id` や `role` による絞り込みが確実で、他園のデータ参照や権限外操作ができないか。
- 現場の操作性: ボタンの押しやすさ、二重送信防止、Loading表示などが現場のミスを誘発しないか。

### コード品質・可読性
- 変数・関数名がドメイン用語（Child, Staff, Attendance, Plan等）に基づいているか。
- マジックナンバーを避け、定義済みの定数やEnumを使っているか。
- `partials/common/` 等の共通パーツを適切に利用し、重複実装を避けているか。
- `var_dump`, `console.log`、不要な古い関数・CSSが残っていないか。

### フロントエンド（CSS/JS）
- PHPファイル内のインラインスタイルを避け、CSSファイルに分離しているか。
- `!important` を安易に使わず、CSS構文や詳細度に問題がないか。
- TypeScriptで `any` を使わず、適切なインターフェースを定義しているか。

### パフォーマンス・安全面
- N+1問題、大量データ表示時のページネーション、インデックスに問題がないか。
- XSS対策（エスケープ）やSQLインジェクション対策があるか。

## 判定基準

- ✅ Approve: そのままマージ可能。軽微な改善提案は含めてよい。
- 💬 Comment: 実装意図の確認や今後の改善。マージはブロックしない。
- ❌ Request Changes: バグ、権限不備、重大なレイアウト崩れ、年度処理の誤りなど要修正。

## レビュー結果

変更範囲を `git status` / `git diff` で確認し、指摘を重大度順に日本語で報告してください。各指摘にはファイル名・行番号・問題・修正案を含めてください。指摘がなければ「指摘なし」と明記してください。

複雑なロジックや既存の仕組みでは対応が難しかった箇所、スクリーンショットまたは動画、PCとタブレット（iPad等）での動作確認についても確認してください。
